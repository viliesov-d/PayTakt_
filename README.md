# PayTakt 2.0.0 beta 2 — персональний майстер налаштування

Передрелізний проєкт React + TypeScript + Firebase, побудований на PayTakt 1.0.0.

## Новий сценарій користувача

1. Реєстрація / вхід у Firebase Authentication.
2. Для **нового порожнього робочого простору** автоматично відкривається покроковий майстер:
   - сфера роботи (основні 9 або всі 17);
   - рекомендований графік, з можливістю показати всі та створити власний;
   - основний спосіб оплати, включно з «Вводжу заробіток сам» — без обов’язкової фіксованої ставки;
   - окреме запитання «Як рахувати понаднормові?» (немає / кнопка / після заданої кількості годин);
   - тільки відповідні професії функції: каса, нічні та план/премія обираються окремо;
   - аванс, зарплата й дата премії;
   - перевірка результату перед збереженням.
3. Після завершення відкривається «Мій календар» з персональними кнопками. Для виробництва без каси немає «Увімкнути касу», для магазину цей модуль доступний. Понаднормові не показуються, коли вимкнені. Ручна зарплата відкриває поле «Мій заробіток за день», але не створює фіксованої базової ставки.
   Для рідкісних випадків необов’язкову касу можна ввімкнути в «Налаштування роботи» → «Інші можливості».

4. Після завершення відкривається «Мій календар». Основна навігація: «Мій календар», «Мої гроші», «Налаштування роботи».
5. Всі попередні детальні правила залишаються в «Налаштування роботи» → «Усі правила оплати» / «Редактор графіків».

**Власники наявних даних не проходять майстер повторно автоматично.** Його можна вручну відкрити в налаштуваннях. Важливо: повторне завершення змінить правила оплати. Існуючі календарні записи при цьому не перезаписуються.

### Як зберігаються дані

- Проміжні відповіді — чернетка в localStorage, прив'язана до UID і робочого простору; це не резервне копіювання.
- Після явного підтвердження застосунок додає відсутні дні поточного й наступного місяця, створює редагований шаблон графіка, записує необов'язкові правила каси та премій, а потім основні правила оплати у вже наявні Firestore-колекції.
- Календар не перезаписує заповнені дні; старі ставки не змінюються без підтвердження.
- Якщо якийсь запис не пройшов, майстер зберігає відповіді й показує помилку. Деякі попередні кроки запису могли встигнути зберегтися; повторна спроба додає лише відсутні дні.

### Встановлення (PowerShell)

```powershell
npm.cmd install
npm.cmd test
npm.cmd run build
npm.cmd run dev
```

Скопіюйте `.env` зі свого працюючого проєкту PayTakt 1.0.0. Не публікуйте його у GitHub. Приклад потрібних назв — у `.env.example`.

**Firestore Rules залишено без змін від PayTakt 1.0.0**. Нові Firebase-колекції для майстра не потрібні.

### Перевірки

- Автоматичні логічні тести — `npm.cmd test`.
- Сувора перевірка нового розрахункового модуля TypeScript виконана.
- Синтаксис TS/TSX перевірений.
- Повна Vite-збірка не підтверджена тут: npm-реєстр недоступний. Перш ніж публікувати, потрібно виконати `npm.cmd run build` та пройти чекліст `BETA-QA-UA.md` на ПК й телефоні.

Обчислення зарплати — орієнтовні, не податковий або юридично підтверджений розрахунок. Підтримка працівників компанії з ролями — майбутній етап.

## Beta 2: як визначається видимість

- **Сфера роботи** дає рекомендації. Каса пропонується в торгівлі, ресторанах/готелях та сфері краси; для інших професій доступна за свідомим запитом.
- **Вибрані функції** визначають кнопки: каса — лише при ввімкненні; швидкі понаднормові — лише в ручному режимі; автоматичні понаднормові працюють без зайвої кнопки.
- **Ручний заробіток** налаштовується без обов’язкової ставки. За потреби окремої доплати за понаднормові або нічні години вказується погодинна *база для доплат*, не фіксована зарплата.
- **Збережені дані не видаляються** при приховуванні функцій. Розширені правила та касу можна відкрити з «Налаштувань роботи».

Це тестова версія. Автоматичні тести та синтаксис перевірені, але повну збірку `tsc -b && vite build` і Firebase у браузері потрібно перевірити локально.
