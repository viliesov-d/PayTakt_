# PayTakt для iPhone — перша iOS-версія 0.1.0

База — Android 0.9.17. Дані, календар і зарплатні розрахунки спільні; iOS має окрему нумерацію в `ios-version.json`. Android APK і його перевірка оновлень не змінюються.

## Що реалізовано

- Проєкт Xcode `ios/App/App.xcodeproj`, Capacitor 8, Swift Package Manager.
- iOS 15+, iPhone та iPad; іконка PayTakt, світла/темна тема.
- Мобільна навігація з рухомою капсулою, кольорами й прозорістю; безпечні відступи навколо вирізу екрана та Home Indicator.
- Локальні нагадування за явною згодою, до 64 найближчих подій. Перепланування при відкритті/поверненні до застосунку. Доставка залежить від дозволів і системних режимів.
- Вимкнене пружне розтягування WKWebView; звичайний скрол збережено.
- iOS не перевіряє й не пропонує встановлювати Android APK.

**Скло:** Android SVG-заломлення не змінено. У WKWebView використовується наявний CSS blur/saturation fallback; це не нативний Apple Liquid Glass і не ідентичний оптичний ефект. Подвійну рефракцію на iPhone ще не реалізовано та не підтверджено.

## Перша локальна перевірка на Mac

Потрібні Node 22+, Xcode 26 із платформою iOS. Встановити залежності з кореня проєкту:

```sh
npm ci
npm run ios:sync
npm run ios:open
```

У Xcode обрати схему `App` та iPhone Simulator, потім Run. Для реального облікового запису потрібні ті самі `VITE_FIREBASE_*`, що для вебверсії: `.env.local` або змінні середовища. Без них використовуй деморежим. Після зміни вебкоду знову виконати `npm run ios:sync`.

Для власного iPhone: підключити телефон, відкрити Signing & Capabilities, обрати свою Team, за потреби встановити доступний Bundle Identifier та ввімкнути Developer Mode на пристрої. Підпис і provisioning налаштовуються у власному Apple-акаунті; пароль/ключі не додаються в Git.

## GitHub Actions без Mac у розробника

Workflow **iOS simulator build** запускається для PR зі змінами iOS/застосунку й вручну після злиття. Він збирає Debug `.app` на macOS без підпису. Артефакт `PayTakt-iOS-Simulator.zip` призначений **тільки для симулятора на Mac**. Це не IPA для встановлення на iPhone.

Firebase-параметри workflow бере з наявних GitHub Secrets. У зовнішньому fork PR secrets недоступні, тому така збірка придатна лише для деморежиму.

## TestFlight / App Store — окремий наступний крок

Потрібні Apple Developer Program, App ID/App Store Connect, підпис і provisioning profile. Спочатку визначити спосіб розповсюдження та виконати перевірку на реальному пристрої. Ця зміна не створює App Store-запис, не публікує застосунок і не містить ключів підпису. Для релізу також підготувати політику конфіденційності, відомості App Privacy та перевірити вимоги до видалення акаунта.

## Перевірка перед розповсюдженням

- Вхід/вихід, запуск після закриття, завантаження Firebase та офлайн-синхронізація.
- Виріз екрана/Home Indicator, поворот iPhone й iPad, клавіатура в редакторі дня.
- Натискання, перетягування й скасування жесту навігації; збільшений текст.
- Світла/темна тема, системні іконки, прозорість; читабельність CSS-скла.
- Запит дозволу, доставка та скасування нагадувань на реальному iPhone.
