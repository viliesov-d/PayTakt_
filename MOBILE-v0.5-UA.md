# PayTakt Mobile v0.5 — справжня валюта зарплати

## Що змінюється

- Новий особистий або корпоративний робочий простір можна створити з
  обліковою валютою **UAH, USD, EUR, PLN або GBP**.
- Вибрана валюта справжня: числові суми зарплати, погодинних ставок,
  грошової каси, планів, премій, комісій і подій виплати **зберігаються
  як соті частки цієї валюти**, а не як конвертовані гривні.
- Наприклад, у просторі з USD ставка 20.50 означає 20 доларів 50 центів,
  а не гривні. Розрахункова математика лишається незмінною.
- Курс обміну не потрібен для нарахування зарплати в просторі з USD.
  Налаштування «валюта відображення» з v0.3 діє тільки для **старих
  гривневих просторів**, де показує приблизний перерахунок вручну.
- Для старих просторів, які не мають поля `currency`, завжди діє UAH.
  Жодні збережені суми, касові записи, премії й графіки не мігруються.

## Чому валюту простору не можна змінити після створення

Суми зберігаються як цілі числа (у сотих частках). Якщо просто замінити
UAH на USD, старі 31 000 грн перетворилися б на 31 000 доларів без
конвертації. Щоб цього не сталося, правила Firestore забороняють
змінювати валюту в існуючому просторі.

Для іншої валюти **створи новий особистий чи корпоративний простір**.
Існуючий гривневий простір залишиться у списку та його дані збережуться.
Міграція старих записів між валютами можлива лише в майбутній окремій
функції з явним курсом, попереднім переглядом і перевіркою всіх сум.

## Важливо: розгортання Firestore Rules

GitHub Pages і GitHub Actions **не публікують Firestore Rules автоматично**.
Зміни в `firestore.rules` у репозиторії — це ще не чинні правила бази.

Для можливості створювати простори з USD/EUR/PLN/GBP потрібно:
1. Після перегляду PR відкрити повний файл
   `firestore.rules` із оновленої гілки або з `main` після злиття.
2. Відкрити Firebase Console → Firestore Database → **Rules**.
3. Заміни *весь* текст правил файлом із GitHub, переконайся, що він
   стосується правильного Firebase-проєкту, і натисни **Publish**.
4. Тільки після успішної публікації використовуй «Новий робочий простір»
   з іншою валютою. Без правил Firebase поверне permission denied.
5. **Не використовуй тестові відкриті правила** `allow read, write: if true`.

Гривневі простори лишаються сумісними зі старими правилами.

## Як протестувати

1. Перевір, що існуючий особистий простір лишився UAH, а суми збігаються.
2. Після оновлення правил створи новий **особистий** простір з USD
   через «Налаштування → Додати робочий простір».
3. Внеси тестову погодинну ставку 20.50: у правилах і статистиці
   вона має відображатися як `$20.50` (залежно від мови форматування).
4. Запиши касу та премію — їхня одиниця теж USD, **без** символу `≈`.
5. Переключись назад на попередній UAH-простір: збережені записи мають
   залишитися гривневими. Перевір результат і на Android, і у вебверсії.
6. У налаштуваннях USD-простору поле з курсом UAH/USD не повинно
   показуватися: він не бере участі в обліку.
7. Не використовуйте шаблон «Система Зміна» для іншої валюти:
   у v0.5 він вимкнений для не-гривневих просторів, щоб не призначити
   гривневу премію у доларах.

## Інсталяція Android

Після того як Pull Request об'єднано з `main`, в GitHub →
Actions → **Android debug APK** → **Run workflow** (`main`).
Завантажити артефакт, розпакувати `app-debug.apk`, встановити.
Важливі дані мають бути синхронізовані з Firebase перед можливою
переінсталяцією через відмінний debug-підпис.

## Наступні етапи

- Завершення перекладів усіх складених і динамічних повідомлень.
- Офлайн-зміни з чергою операцій і правилами конфліктів.
- Android-сповіщення про зміни та дати зарплати.
- Підпис release APK одним ключем і зручні наступні оновлення.
