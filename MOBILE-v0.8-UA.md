# PayTakt Mobile v0.8 — компактна синхронізація та сповіщення Android

## 1. Маленький статус синхронізації

З календаря й інших основних сторінок **прибрано великий інформаційний блок**
«Збережено у Firebase / Локальні записи: 0».

Його нове місце — **Налаштування**, компактна однорядкова смужка:
- **«Збережено»** — немає локальної черги, мережа доступна.
- **«Очікуємо мережу»** — пристрій офлайн.
- **«Очікує синхронізації»**, «Синхронізація», «Конфлікт», «Помилка» —
  за відповідного стану.

Натискання розгортає деталі й дії: повторна синхронізація, вибір
між локальною та серверною версією. Всі механізми v0.7 залишилися без змін.

## 2. Нативні Android-сповіщення

Новий блок **Налаштування → Нагадування Android**:

- Увімкнення — **лише після натискання кнопки** та надання дозволу Android.
- **Перед зміною:** 15, 30, 60 або 120 хв до початку запланованої
  (ще не відпрацьованої) робочої зміни.
- **Про завтрашній день:** о вибраній годині напередодні зміни.
- **Про зарплату:** о вибраній годині у дату, передбачену активними
  правилами виплат (з урахуванням виплат наступного місяця).
  Це нагадування про *заплановану* дату, а не підтвердження надходження грошей.
- Кожен тип можна вимкнути незалежно, або вимкнути всі сповіщення.
- Налаштування окремі для кожного акаунта й робочого простору.
- Показано число запланованих нагадувань, повідомлення про відмову
  в дозволі й посилання-інструкцію, що Android може затримувати нагадування.

**Робота із закритим застосунком:** плагін Capacitor
`@capacitor/local-notifications@8.3.1` зберігає у системі Android
локальні нагадування на **найближчі 28 днів** (до 64 подій).
Заплановані сповіщення можуть показуватися, коли PayTakt закритий.

**Важливо:** оновлення розкладу сповіщень відбувається лише тоді, коли
PayTakt відкритий/повертається на передній план. Нові зміни, яких застосунок
ще не завантажив із Firebase, не зможуть автоматично перепланувати
нагадування під час повністю закритої програми. Якщо застосунок
не запускати понад 28 днів, старий набір закінчиться.

**Точність:** нагадування використовують неточні Android alarms
(`isExactNotification:false`), щоб не вимагати спеціального
`SCHEDULE_EXACT_ALARM`. Система може доставляти їх із затримкою
через енергозбереження й оптимізацію батареї. Android 13+
запитує дозвіл на показ сповіщень.

**Браузер:** локальні Android-сповіщення недоступні у вебверсії.
На вебсайті показується пояснення без прохання про дозволи.

## 3. Android-збірка

У `scripts/setup-android.mjs` до встановлення Android SDK через
Capacitor sync додано `@capacitor/local-notifications@8.3.1`.
`npm ci` у звичайній веб-версії не змінюється.
Native bridge `window.Capacitor.Plugins.LocalNotifications` працює
лише у нативному WebView після встановлення плагіна.
Важливо: **звичайний web build не доводить, що нативний плагін
працює на телефоні** — перевір APK на реальному Android.

## 4. Перевірка

1. У GitHub PR перевір `Check PayTakt` = Success.
2. Злий PR у `main`. У GitHub → Actions → Android debug APK →
   Run workflow (гілка `main`), потім завантаж `PayTakt-Android-debug`.
3. Перед установкою APK завершити всі офлайн-синхронізації v0.7.
4. Відкрити Налаштування: маленький статус «Збережено», без великого
   банера на календарі. Вимкнути інтернет: «Очікуємо мережу».
   Якщо є конфлікт, розгорнути статус і переконатися, що рішення доступне.
5. Налаштування → Нагадування Android → Увімкнути нагадування →
   дозволити сповіщення у Android.
6. Додати тестову **заплановану** зміну на завтра, час початку —
   поточний час плюс кілька годин. Перевірити, що статус показує
   число запланованих подій.
7. Закрити PayTakt. Перевірити нагадування перед зміною та про
   завтрашній день у заданий час. Android може показати їх не точно.
8. У Налаштування → Правила оплати перевірити дату наступної виплати;
   сповіщення «Запланована виплата» має бути в календарі планування.
9. Вимкнути конкретний тип і потім всі — Android-розклад PayTakt
   має очиститися.
10. Переключити робочий простір або вийти з акаунта —
    старі нагадування не повинні залишатися активними.

## 5. Firestore Rules

Для v0.8 **оновлення Firestore Rules не потрібне**. Жодні дані
сповіщень не додаються до Firebase. Це локальні налаштування Android.
