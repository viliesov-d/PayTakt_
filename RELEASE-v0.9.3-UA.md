# PayTakt v0.9.3 — необов'язкова каса за день

Це **повна версія проєкту**, заснована на v0.9.2. Попередні графіки, оклади, понаднормові, виплати та статистика збережені.

## Що додано

- **«Каса»** — невеликий перемикач над календарем. Для робочих просторів за замовчуванням вимкнений, щоб не перевантажувати сайт для інших професій. Налаштування зберігається у Firestore в `workspaces/{id}/settings/cash`.
- **«Каса за день»** — згорнутий за замовчуванням розділ редактора робочого дня: сума у гривнях, збереження та очищення. Після збереження день отримує маленьку позначку «Каса». Значення зберігається у `workspaces/{id}/dailyCash/{YYYY-MM-DD}` у **копійках**.
- **Журнал каси у «Статистика»** — один згорнутий блок із сумою за місяць, датами, типами змін, сумами та **орієнтовною базовою оплатою за день** з календаря. Базова оцінка **не включає** премії, тарифні ступені, нічні та понаднормові; точні нарахування див. у «Нарахування».
- Вихідний, відпустка, лікарняний, «За свій рахунок» і записи без робочої зміни **не враховуються у сумі каси**, навіть якщо колись були збережені. Дані фізично не видаляються автоматично; їх можна прибрати вручну.
- За бажанням можна увімкнути **«Використовувати щоденну касу для % від виручки та плану продажів»**. Тоді денні суми **заміщують** ручну місячну виручку (вони ніколи не додаються одна до одної, щоб не подвоювати комісію). Каса сама по собі не додається до особистого окладу. Якщо не вмикати зв'язок, журнал не впливає на нарахування.
- Для цієї нової можливості додані **обмежені власником Firestore Rules**. В інших колекціях права не розширюються.

## Встановлення

1. Розпакуй новий ZIP до окремої папки й перенеси свій `.env` з v0.9.2. Не публікуй його в GitHub.
2. Firebase Console → проєкт **paytakt** → Firestore Database → база **(default)** → Rules. Збережи копію старих правил, потім опублікуй **повний** `firestore.rules` із v0.9.3. Це обов'язково: нова колекція `dailyCash` та `settings/cash` не доступні зі старими правилами.
3. Перевір, що в правилах `paySettings/current` залишено робочу перевірку **`ownWorkspace(workspaceId) && request.resource.data.version == 5`**. Не підміняй її старою суворою `validPaySettings()`, яка давала помилку у твоєму проєкті. Файл v0.9.3 зберігає чинний робочий варіант з v0.8.6/v0.9.2.
4. У Windows PowerShell виконай:
   ```powershell
   npm.cmd install
   npm.cmd test
   npm.cmd run build
   npm.cmd run dev
   ```
5. Відкрий **Календар → «Увімкнути касу»**; познач робочий день; натисни **«Каса за день»**, введи суму і збережи. Згодом відкрий **Статистика → «Каса за день · журнал»**.

> `npm.cmd run build` необхідно виконати на своєму комп'ютері. У середовищі підготовки архіву немає доступу до npm-реєстру, тому повну Vite-збірку там неможливо підтвердити. Наявні тести, нові тести логіки й синтаксис TSX перевірені окремо.

## Обмеження

- **Каса = оборот**, а не гроші, які отримав працівник. Заробіток і понаднормові рахуються окремо.
- Каса за день доступна тільки після збереження робочого дня. Записи вихідних не входять в обіг; фізично зберігаються до очищення.
- Перемикач каси зберігається на рівні обраного робочого простору; записів інших просторів він не зачіпає.
- Деморежим зберігає касу лише в пам'яті поточного сеансу.
- Для реальних грошей бажано додатково зберігати бекапи Firestore; функція не призначена для фіскальної звітності.
