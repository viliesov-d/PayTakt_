# Діагностика «власника підтверджено, але paySettings/current відхилено»

Власника перевірено через читання робочого простору, але це не гарантує, що документ правил зарплати відповідає `validPaySettings` або що саме ці Rules активні на сервері.

## Крок 1. Перевірте опубліковані Rules

- Подивіться `VITE_FIREBASE_PROJECT_ID` у вашому локальному `.env`, не надсилайте `.env` повністю або будь-які токени.
- У Firebase Console оберіть цей проєкт → Firestore Database → база `(default)` → Rules.
- Переконайтеся, що правила дійсно **опубліковані**, а не просто вставлені в редактор.
- У Rules має бути `match /paySettings/{payId}` з `payId == 'current'`, `ownWorkspace(workspaceId)` і `validPaySettings()`, та `request.resource.data.version == 5`.
- Якщо там інша версія — замініть **весь** файл на `firestore.rules` з v0.8.4 й натисніть **Publish**. Схема правил у v0.8.4 не ослаблена порівняно з v0.8.3.

## Крок 2. Повторіть запис із v0.8.4

У старих документах вкладені `paymentRules`, `bands` та `customRules` могли містити невідомі ключі. Новий код видаляє їх перед збереженням без зміни легальних полів або числових значень. Відкрийте «Правила оплати» і збережіть знову.

## Крок 3. Rules Playground

1. У Firestore Database → Rules відкрийте **Rules Playground**.
2. Шлях: `workspaces/<workspaceId>/paySettings/current`.
3. Операція `create`, якщо документа немає, або `update`, якщо він уже існує.
4. Увімкніть автентифікацію з UID *власника* робочого простору (`ownerUid`).
5. Для перевірки обов'язково використовуйте **весь** документ із `version: 5`, усіма обов'язковими полями та вкладеними масивами, а не лише кілька змінених полів.
6. Зверніть увагу: Rules Playground симулює **правила з редактора**. Реальну роботу перевіряйте після Publish. Для відстеження конкретних підвиразів зручно використовувати Firebase Emulator Suite (Firestore → Requests).

Для локальних тестів із Firebase Emulator Suite використовуйте тести `@firebase/rules-unit-testing`, з дозволеним записом від власника і забороненим записом від стороннього UID. Це окрема інтеграційна перевірка й не замінюється тестами зарплатної математики.

## Якщо помилка залишається

Для наступної діагностики потрібні: текст опублікованих Rules (без приватних даних), `version` документа `paySettings/current`, результат Rules Playground (Allowed/Denied) та тип операції (`create` або `update`). Не надсилайте Auth-токенів, приватні ключі, паролі або вміст усіх персональних нарахувань.

**Не змінюйте правила на `allow read, write: if true`.** Це відкриє приватні дані.
