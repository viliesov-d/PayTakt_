# PayTakt Mobile v0.9 — назви, видалення просторів і стабільні оновлення

## 1. Дрібні виправлення інтерфейсу

- «Нараховано до податків» на картці статистики → коротко **«Нарахування»**.
- Під час видалення простору не потрібно вводити його назву. Замість цього
  показується **«Ви впевнені?»** та кнопки **«Скасувати» / «Так, видалити»**.
- Попередження про безповоротну втрату даних лишається.
- Не можна видалити останній робочий простір. Видалення все ще очищає
  всі підтримувані колекції Firebase та вимагає з'єднання.

## 2. Оновлення з GitHub Releases

В Android PayTakt:

- На старті й при поверненні в застосунок періодично перевіряє
  останній **публічний** GitHub Release:
  https://api.github.com/repos/viliesov-d/PayTakt_/releases/latest
- Порівнює встановлену версію з `tag_name` у форматі `v0.9.1`.
- Приймає лише активний стабільний реліз (не чернетку чи prerelease)
  й **точно названий APK** `PayTakt-Android-release.apk` з офіційного
  `https://github.com/viliesov-d/PayTakt_/releases/download/v…/`.
- Показує маленьку позначку біля профілю, якщо є оновлення.
- **Налаштування → Оновлення PayTakt**: встановлена версія,
  результат перевірки, «Перевірити оновлення», «Завантажити оновлення»,
  посилання на GitHub Releases.
- Після натискання відкривається **системний браузер Android** для
  завантаження APK. PayTakt **не встановлює APK без згоди користувача**.
  Android може попросити дозволити встановлення з цього джерела.
- Якщо на пристрої є офлайн-записи, кнопка завантаження заблокована.

Для браузерної вебверсії перевірка APK не запускається.

## 3. Важлива межа: debug APK → release APK

**Android дозволяє оновлювати поверх старого APK лише з тим самим
`applicationId` і тим самим сертифікатом підпису та відповідним
`versionCode`.** У PayTakt ID: `ua.paytakt.mobile`.

Раніше `Android debug APK` формувався в GitHub Actions зі стандартним
**тимчасовим debug-ключем**. Кожна нова збірка на іншому runner могла
отримати інший підпис. Зараз ми створюємо **один постійний release-ключ**.

**Перший перехід на стабільну гілку може вимагати видалення debug APK**,
якщо Android показує «Застосунок не встановлено», «Пакет конфліктує»
або «Підписи не збігаються». Видалення стирає локальні дані,
налаштування і чергу офлайн-записів. Тому перед першим переходом:

1. Підключи інтернет. У Налаштуваннях відкрий статус синхронізації.
   Переконайся: **«Збережено», локальних записів 0, конфліктів 0**.
2. Перевір на іншому пристрої або у браузері, що Firebase містить
   останні зміни календаря, каси та налаштувань.
3. Запиши окремо важливі **локальні** параметри (ручний курс НБУ,
   налаштування сповіщень, інші персональні налаштування),
   які не зберігаються у Firebase.
4. Спробуй встановити release APK поверх старого без видалення.
   **Якщо Android відмовить**, тільки після резервування даних
   видали старий debug APK і встанови стабільний.
5. Увійди у свій Firebase-акаунт — синхронізовані дані повернуться.

**Після цієї одноразової міграції** майбутні release APK, підписані
тим самим постійним ключем, зможуть оновлюватися поверх встановленої
програми, зберігаючи її локальні дані.

## 4. Один раз: створити підписний ключ (ПК)

> Не надсилай мені, у чат, або в GitHub файли `.jks` чи паролі.
> Створи і зберігай їх тільки у себе; у GitHub додавай через Secrets.

На Windows у PowerShell (потрібен Java JDK, команда `keytool`):

```powershell
mkdir "$HOME\Documents\PayTakt-release"
cd "$HOME\Documents\PayTakt-release"
keytool -genkeypair -v -keystore paytakt-release.jks -storetype PKCS12 -alias paytakt -keyalg RSA -keysize 3072 -validity 10000 -dname "CN=PayTakt, OU=Mobile, O=PayTakt, C=UA"
```

Програма запитає пароль ключового сховища. Для PKCS12 пароль ключа
зазвичай збігається з паролем сховища. **Збережи файл `.jks` та паролі
у двох безпечних незалежних місцях** (не у публічному репозиторії).
Втрата ключа робить майбутні оновлення існуючих APK неможливими.

Скопіюй Base64 вміст ключа в буфер обміну локально:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("$PWD\paytakt-release.jks")) | Set-Clipboard
```

GitHub → `viliesov-d/PayTakt_` → **Settings → Secrets and variables →
Actions → New repository secret**. Додай 4 Secrets:

| Назва | Значення |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | встав Base64 з буфера |
| `ANDROID_KEYSTORE_PASSWORD` | пароль сховища |
| `ANDROID_KEY_ALIAS` | `paytakt` |
| `ANDROID_KEY_PASSWORD` | пароль самого ключа (для PKCS12 зазвичай той самий) |

**Не записуй** паролі у workflow, файли чи PR. Якщо секретів немає,
релізна збірка **відмовиться** підписувати APK.

## 5. Як створити офіційний release APK

1. Об'єднай PR #9 у `main` після зелених перевірок.
2. Створи всі 4 секрети з розділу вище.
3. GitHub → Actions → **Android signed release APK** → **Run workflow**.
4. Гілка: `main`; версія: **`0.9.0`**.
5. Після успішного завершення GitHub автоматично створить
   **Release v0.9.0** з файлом **`PayTakt-Android-release.apk`**.
6. Завантаж цей APK з **GitHub Releases** (не з меню debug artifacts).
7. Під час наступних релізів зміни в `mobile-version.json`
   `version` і **збільш** `versionCode`; використовуй ті самі Secrets.

Робочий процес:
- Після `npm run android:setup` програма встановлює
  `versionName=0.9.0`, `versionCode=90000`, ID `ua.paytakt.mobile`
  в згенерованому Android Gradle.
- `assembleRelease` → `zipalign` → `apksigner sign` з приватним ключем
  із Secrets → `apksigner verify` → перевірка ID/версії → GitHub Release.
- Секретний ключ не зберігається у Git і видаляється з runner.
- У GitHub Releases зазначається SHA-256 файлу.

`Android debug APK` залишається **лише для розробки**. Довготривалі
оновлення потрібно випускати саме через **Android signed release APK**.

## 6. Перевірка

- Статистика → картка «Нарахування».
- Налаштування → Робочі простори → тестовий другий простір →
  «Видалити» → «Ви впевнені?», без поля вводу.
- Налаштування → Оновлення PayTakt показує встановлену версію.
- До публікації Release сторінка показує, що стабільний APK відсутній.
- Після релізу v0.9.0 той же APK показує «Актуальна версія».
- Після майбутнього v0.9.1 APK v0.9.0 показує **«Доступна нова версія»**,
  а натискання «Завантажити оновлення» відкриває офіційний GitHub.
- Дані Firebase, авторизація й локальні параметри зберігаються при
  **звичайному оновленні поверх тієї ж підписаної версії**.
- Для v0.9 **не потрібні нові правила Firestore**.

## Обмеження

Оновлення не встановлюється самостійно у фоні. Без підписного
ключа і GitHub Secrets стабільний реліз створити неможливо.
Перевірка оновлень потребує інтернету й публічного GitHub Release.
