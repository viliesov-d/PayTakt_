# Адмінпанель PayTakt

Вхід: кнопка зі щитом у верхній панелі або «Налаштування роботи → Адмінпанель користувачів». Кнопка з’являється лише для акаунта з Firebase Auth custom claim `admin: true`. Звичайний користувач не може сам призначити цю роль, навіть прямим записом у Firestore. Демо не має доступу.

## Увімкнення

1. Опублікуй `firestore.rules` із цього оновлення у Firebase Console → Firestore Database → Rules для бази `(default)`. Або виконай `firebase deploy --only firestore:rules --project YOUR_PROJECT_ID`.
2. У Firebase Authentication → Users скопіюй UID свого акаунта.
3. На довіреному комп’ютері налаштуй Application Default Credentials для адміністратора Firebase (наприклад, `gcloud auth application-default login`). Обліковому запису потрібне право оновлювати Firebase Auth users. Не додавай сервісні ключі у сайт, `.env` з префіксом `VITE_` чи репозиторій.
4. Виконай:

```powershell
npm.cmd --prefix scripts/admin install
node scripts/admin/set-admin.mjs YOUR_PROJECT_ID YOUR_USER_UID grant
```

5. Вийди з PayTakt та увійди знову. Відкрий кнопку зі щитом.

Відкликання ролі: та сама команда з `revoke` замість `grant`. Уже виданий ID token може залишатися чинним до завершення строку його дії (приблизно година); оновлення адмінпанелі примусово оновлює токен.

## Що означають показники

- **Користувачів:** кількість документів `users` у Firestore, а не повний список Firebase Auth. Акаунти без профілю сюди не входять; видалення лише Auth-акаунта не видаляє його профіль.
- **Нових за 7 днів:** профілі з `createdAt` протягом останніх 168 годин.
- **Активні за 24 години / 7 / 30 днів:** профілі з `lastSeenAt` у відповідному рухомому вікні.
- Активність записується приблизно раз на 5 хвилин лише при відкритому застосунку, авторизованому користувачі та доступному інтернеті. Це приблизна активність, не точний онлайн-статус.
- Платформа — остання використана: web (сайт або PWA), Android, iOS. Не кількість встановлень.
- Графік — 7 календарних днів у часовому поясі браузера адміністратора, який підписано в панелі. Сьогодні неповний день.
- Старі профілі без дат не виключаються зі списку чи загальної кількості. Невідома історія відображається як «Немає даних» і не відновлюється штучно.
- Список містить до 25 записів на сторінці, пошук за точною повною email-адресою. Кнопка «Далі» переходить до наступної сторінки; «На початок» повертає першу.

Профілі читаються через Firestore REST із користувацьким ID token. Security Rules перевіряють адміністратора на сервері. Відповіді не записуються в IndexedDB/localStorage; помилка доступу очищає показані дані. Статистика агрегується на сервері, фінансові дані чужих робочих просторів адміністратору не відкриваються. Запити агрегацій і читання профілів враховуються в тарифікації Firestore. Дати створення профілю після оновлення правил не можуть змінюватися клієнтом; дата активності приймається лише як server timestamp.

## Сайт і Android

Спільний компонент розкриття оновлює сайт і мобільну збірку. Для Android підготовлено версію 0.9.22 (92200). Після злиття запусти workflow **Android signed release APK** для `main`; він створює підписаний APK. Саме оновлення сайту не оновлює встановлений APK.

Порядок: Firestore Rules → роль адміністратора → оновлення сайту / APK. Без нових Rules зарплатні функції продовжують працювати, але запис активності й адмінпанель не працюватимуть.
