# Адмінпанель PayTakt

Вхід: кнопка зі щитом у верхній панелі або «Налаштування роботи → Адмінпанель користувачів». Кнопка з’являється лише для акаунта з Firebase Auth custom claim `admin: true`. Звичайний користувач не може сам призначити цю роль, навіть прямим записом у Firestore. Демо не має доступу.

## Увімкнення

1. Опублікуй `firestore.rules` із цього оновлення у Firebase Console → Firestore Database → Rules для бази `(default)`. Або виконай `firebase deploy --only firestore:rules --project YOUR_PROJECT_ID`.
2. У Firebase Authentication → Users скопіюй UID свого акаунта.
3. На довіреному комп’ютері у Firebase Console → Project settings → Service accounts → Firebase Admin SDK створи приватний ключ. Збережи JSON поза папкою репозиторію, наприклад у Downloads як `paytakt-admin.json`. У PowerShell задай `$env:GOOGLE_APPLICATION_CREDENTIALS = "$env:USERPROFILE\Downloads\paytakt-admin.json"`. Не надсилай ключ у чат і не додавай його у сайт, `.env` з префіксом `VITE_` чи репозиторій. Звичайний `gcloud auth application-default login` без власного OAuth client ID не підходить для Firebase Authentication: https://firebase.google.com/docs/admin/setup#test_with_gcloud_end_user_credentials .
4. Виконай:

```powershell
npm.cmd --prefix scripts/admin install
node scripts/admin/set-admin.mjs YOUR_PROJECT_ID YOUR_USER_UID grant
```

5. Вийди з PayTakt та увійди знову. Відкрий кнопку зі щитом. Після успішного одноразового налаштування видали саме новостворений ключ у Google Cloud IAM → Service Accounts → відповідний сервісний акаунт → Keys, а також локальний JSON. Не видаляй інші ключі, які можуть використовуватися сервісами.

Відкликання ролі: та сама команда з `revoke` замість `grant`. Уже виданий ID token може залишатися чинним до завершення строку його дії (приблизно година); оновлення адмінпанелі примусово оновлює токен.

## Адмінпанель у стилі «Зміна 2.0»

Адмінпанель PayTakt замінює попередню таблицю статистики. Оформлення й структура перенесені з viliesov-d/YAPPI_ (проєкт «Зміна»): темно-синій hero із лаймовими акцентами, п'ять карток загальних KPI, графіки, ТОП за касою, список працівників ліворуч, картка вибраного працівника праворуч. На телефоні дві колонки переходять в одну.

- **Звітний місяць** і **валюта** обираються у шапці. Гривні, долари, євро та інші валюти не додаються між собою.
- **Загальна каса** — внесені дані каси за днями; **зарплата команди** — перерахунок за чинними правилами PayTakt; **премії** — сума відповідних бонусних рядків; **виконали план** — кількість робочих просторів із досягнутим планом; **користувачів** — кількість профілів Firestore на сервері.
- **Графіки за днями**: каса та зарплата, введена *вручну за день*. Автоматично нараховану місячну зарплату неможливо достовірно приписати конкретній даті, тому вона відображається у загальних KPI та деталізації, але не видається за щоденний факт.
- **Лідери місяця** — ТОП-5 за внесеною касою в обраній валюті; натискання відкриває картку працівника.
- **Пошук** — за частиною імені або email; **фільтри** — усі, є зміни, без змін, неповні дані; **сортування** — каса, зарплата, план, ім'я.
- **Картка працівника**: зарплата, каса, план, зміни, прогрес, графіки, журнал дат із сумами каси та ручної зарплати, детальні нарахування й доплати. Якщо в користувача кілька робочих просторів, можна вибрати потрібний.
- Є **CSV-звіт команди** (за обраний місяць і валюту) та **JSON-звіт працівника**. Завантаження відбувається тільки після натискання адміністратора; документи не зберігаються в браузерному кеші автоматично.
- У «Зміні» також є «Призупинити синхронізацію». У PayTakt **цю дію не перенесено**, бо вона потребує змін правил роботи акаунтів і синхронізації всього застосунку. Такі зміни виходять за межі завдання. Панель зберігає **доступ лише для читання**.
- Показники обчислюються лише для завантажених профілів. Для захисту від масових Firestore-запитів є обмеження 500 профілів; якщо їх більше, панель явно попереджає про неповне охоплення. Відсутні чи некоректні зарплатні правила показуються як помилки, а не вигадані нулі.
- Дані беруться з Firestore через свіжий ID token адміністратора і *не потрапляють* до офлайн-кешу зарплати. Розрахунок — прогноз за поточними налаштуваннями, а не незмінна історія банківських виплат чи старих ставок.

**Доступ:** Firebase Auth custom claim admin:true та відповідні firestore.rules. Для вже налаштованої адмінпанелі PayTakt правила PR №42 залишаються придатними: у цій зміні правила доступу й основні файли додатка не змінюються.
## Перевірка після оновлення

1. Увійди як адміністратор і відкрий «Адмінпанель».
2. Вибери місяць і валюту; перевір KPI, лідерів, пошук, фільтри та картку користувача з його робочим простором.
3. Порівняй цифри з його розділом «Нарахування». За різних валют перевір окремі суми.
4. Увійди під звичайним акаунтом: адміністративний розділ має бути недоступний. Навіть запит чужого зарплатного документа через Firestore повинен бути відхилений.
5. Якщо бачиш 403 або «Немає доступу до фінансових даних» — перевір Rules і перезайди. Якщо частина нарахувань має помилку, переглянь наявність і коректність зарплатних правил цього простору.

## Сайт і Android

Спільний компонент розкриття оновлює сайт і мобільну збірку. Для Android підготовлено версію 0.9.23 (92300). Після злиття запусти workflow **Android signed release APK** для `main`; він створює підписаний APK. Саме оновлення сайту не оновлює встановлений APK.

Порядок: Firestore Rules → роль адміністратора → оновлення сайту / APK. Без нових Rules зарплатні функції продовжують працювати, але запис активності й адмінпанель не працюватимуть.
