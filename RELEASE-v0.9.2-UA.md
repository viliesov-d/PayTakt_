# PayTakt v0.9.2 — правила вихідних і компактна форма оплати

## Важлива нова опція

**Мої правила зарплати → Основна оплата → Оклад → Як звичайні вихідні змінюють норму окладу.**

- **Вихідні зменшують норму** — якщо запланований будній день вручну позначено «Вихідний», він не входить до норми дня/годин поточного місяця.
- **Завжди використовувати первинний план** — попередня поведінка: вихідний, створений із запланованого робочого дня, залишається у нормі.
- «За свій рахунок» зберігає планову норму, але не оплачується; відпустка й лікарняний теж лишаються у нормі.
- Ця опція застосовується лише коли джерело місячної норми — **Автоматично з календаря**. Для ручної норми нічого не змінюється.
- Старі документи налаштувань, що не мають поля `monthlyOffDayNormMode`, автоматично використовують `keep_planned` до явної зміни.

**Приклад:** оклад 31 000 грн, три заплановані робочі дні: дві зміни відпрацьовано, один день — позначено вихідним. За новим правилом норма 2 дні, прогноз окладу 31 000 грн. Якщо замість вихідного позначити «За свій рахунок» — норма лишиться 3 дні, нараховано ~20 666,67 грн за 2 відпрацьовані. Це лише демонстрація формули, не нормативний розрахунок.

## Інтерфейс

Всі редаговані розділи правил оплати тепер розгортні `<details>`: Основна оплата, Постійні доплати, Нічні години, Визначення понаднормових, Ступені погодинної оплати, Оплата за обсяг, Власні правила, Календар виплат, Додаткова погодинна база (за потреби), Виручка. Перший розділ відкритий після завантаження, решта закриті. Налаштування зберігаються лише після натискання «Зберегти правила».

## Встановлення

1. Розпакуй ZIP окремо. Скопіюй тільки свій `.env` із v0.9.1.
2. `npm.cmd install`
3. `npm.cmd test`
4. `npm.cmd run build`
5. `npm.cmd run dev`
6. Обери режим у новому правилі, натисни «Зберегти правила».

**Firebase:** нових колекцій немає. Якщо у Firebase досі використовуються правила власника з v0.8.6 (`ownWorkspace` + `version == 5`), нічого публікувати не треба. Клієнт перевіряє нове поле локально; серверна деталізована перевірка v0.8.6 досі вимкнена (див. `FIRESTORE-RULES-SAFETY-UA.md`).

**Поведінка:** розрахунки є прогнозом, а не бухгалтерською відомістю. Старі місяці можуть перерахуватися після зміни правила, оскільки налаштування глобальні.
