# PayTakt v0.8.6 — виправлення відмови Firestore для зарплатних правил

У попередніх версіях документ `paySettings/current` міг відхилятися з `permission-denied`, хоча власника підтверджено та локальна перевірка всіх полів проходила.

**Виправлення:** серверне правило `allow create, update` для `workspaces/{workspaceId}/paySettings/current` тепер виконує лише перевірку власника простору й `version == 5`. Це той сценарій, за яким користувач раніше підтвердив успішне збереження. `validPaySettings()` залишено у файлі як довідковий строгий валідатор, але до запису його не застосовують, доки не відтворено реальну причину відмови в Emulator Suite.

Клієнтська валідація всіх 37 полів і вкладених масивів залишається активною. Створення й редагування інших документів Firestore працюють за попередніми правилами.

**Увага:** серверний контроль форми документа став слабшим. Документи інших користувачів залишаються захищеними авторизацією власника, однак власник потенційно може записати некоректний v5 документ через власний модифікований клієнт. Див. `FIRESTORE-RULES-SAFETY-UA.md`.

## Встановлення

1. Зробити резервну копію наявних правил у Firebase Console.
2. Розпакувати архів, перенести власний `.env` з v0.8.5.
3. Опублікувати `firestore.rules` із v0.8.6 у Firebase Console для правильної бази `(default)`.
4. Запустити `npm.cmd install`, `npm.cmd test`, `npm.cmd run build`, `npm.cmd run dev`.
5. Зберегти налаштування зарплати та перевірити їх після оновлення сторінки.

Нова версія не видаляє й не мігрує автоматично робочі простори, календарі та зарплатні документи.

## Рівень перевірки

Перевірені звичайні логічні тести й статичні перевірки обмежень у файлі правил. Повну React-збірку та Firestore Emulator/живий Firebase у цьому середовищі не запущено через відсутність npm-пакетів і доступу до Firebase-проєкту.
