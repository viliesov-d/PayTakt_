# PayTakt v0.8.5 — діагностика запису зарплати і стабільний вибір робочого простору

Цей реліз **не заявляє, що серверну помилку Firestore вже виправлено**. Власник підтверджений, але якщо сервер повертає `permission-denied`, клієнт не бачить, який саме пункт `validPaySettings()` дав false.

## Що змінилося

- Коли користувач входить в акаунт і PayTakt обирає початковий робочий простір, його ID тепер записується в Local Storage. Раніше ID зберігався лише після ручного вибору через меню. Це могло змінювати активний простір при новому вході.
- Перед збереженням v5 зарплати працює додаткова перевірка полів, сум, меж, типів і масивів `bands`, `paymentRules`, `customRules`.
- Якщо є невідповідність, повідомлення показує конкретний шлях (`paymentRules[0].amount` тощо).
- Якщо локальні перевірки пройшли, а Firestore відмовив, повідомлення чесно вказує, що причина на боці оцінки правил і називає **поточний** ID простору. Це не означає, що правила треба послаблювати.
- Firestore Rules не змінено й захист не послаблено. Ніяких міграцій, видалень чи автоматичних перезаписів даних.

## Як оновити

1. Розпакуйте ZIP до окремої папки.
2. Перенесіть ваш локальний `.env` із v0.8.4. Не публікуйте `.env` у GitHub.
3. Виконайте `npm.cmd install`, `npm.cmd test`, `npm.cmd run build`, `npm.cmd run dev`.
4. Увійдіть у PayTakt, виберіть потрібний робочий простір у меню та перевірте його ID.
5. У «Правила оплати» натисніть «Зберегти».
6. Якщо бачите ім’я проблемного поля, скопіюйте тільки його — це допоможе виправити формат. Якщо знову є `permission-denied` при успішній локальній перевірці, потрібна діагностика опублікованих Firestore Rules через Emulator Suite → Requests із тим самим повним документом.

**УВАГА:** Не замінюйте `validPaySettings()` на `version == 5` у продуктивному режимі. Якщо під час попередніх тестів його послаблювали, поверніть повні захищені правила.

## Перевірки

- 105 автоматичних тестів `node --experimental-strip-types --test tests/*.test.mjs` пройшли.
- Змінені розрахункові та діагностичні TS-модулі пройшли сувору перевірку TypeScript.
- Повну React/Vite збірку не вдалося перевірити через відсутність npm-залежностей у середовищі. Команда `npm.cmd run build` обов'язкова на комп'ютері користувача.
